## Interpretation and follow-up

- Prompt processing: median prefill throughput rose from 5,559 tok/s at a median 1,512 prompt tokens to 7,275 tok/s at a median 47,040 prompt tokens; the three longer depths were about 7,181–7,275 tok/s. Each depth had eight measured requests, all successful. This describes this server/configuration only; it is not compared with a prior baseline.
- TP4 end-to-end concurrency: aggregate throughput was 235.4, 375.6, 517.4 and 685.8 tok/s at levels 1, 2, 4 and 8, with 48/48 requests successful at each level. Median per-request decode fell from 288.4 to 120.5 tok/s across those levels. The run used the existing TP4-configured service; it cannot isolate tensor-parallel scaling or collective performance. BetterBench's own GPU inventory listed three cards, while one-second telemetry sampled all four configured BDFs. The recorded launch arguments request TP4, but model-rank placement was not independently verified in this run.
- Token generation: weighted single-stream median decode was 268.1 tok/s, with combined TTFT p50 about 83 ms and update-gap p99 about 12.3 ms. All 160 runs were marked successful, but all streamed multiple tokens per update and 62/160 reached `max_tokens`; per-token ITL and complete-answer quality therefore were not established. The report itself marks p99 values as under-sampled.
- Runtime evidence: across all four GPUs, average GFX utilization was about 97.6% and average GFX clock about 3.21 GHz. Average reported power ranged 258–270 W per GPU, with samples reaching the reported 300 W `max_power`. VRAM remained 99.52–99.56% used. Maximum hotspot readings ranged 92–98 °C; maximum memory temperature ranged 84–91 °C. PCIe bandwidth/replay telemetry was unavailable, so PCIe saturation cannot be assessed. These whole-run readings are not phase-aligned and do not establish a bottleneck.
- Firmware connection: weak and unproven. XFX PPLib ID `0x125b` is a driver-table selection clue in the inspected source, but the exact runtime SMU dispatch and selected table were not established. Recorded resume overdrive-upload errors are consistent with a restore/upload failure path in the source; they do not establish a PPLib cause or an effect during this run. The UMC table exposes no timing/voltage pointer evidence supporting a VBIOS memory-timing change.
- Runtime controls to investigate: first validate the exact board's thermal/power limits and cooling, especially the 98 °C hotspot observation; read current per-GPU performance profile, throttle indicators and supported OD state; establish the active SMU table path; and collect PCIe link/counter data alongside a future phase-timed run. No control is changed or recommended from this diagnostic alone.
- Benefit versus repeated stock results: not established by one run. No improvement claim is made.
