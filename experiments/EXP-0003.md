settings. Build in a separate directory. Reuse the unchanged 1.9.0 engine and
other plugins; only a measured candidate's `libr4d.so` changes for serving trials.

EXP-0002. Retain source/patch/build hashes and exact commands with every result.

The prepared [command manifest](EXP-0003/kernel-v1-manifest.json) pins the trial
self-test executable, NW=16 plugin, stock NW=8 plugin and both supervisor scripts.
It contains 28 commands under a single 1,680-second deadline. The native gfx1201
build succeeded; its [log](EXP-0003/build-v1/build-v3.log) and full [source
preparation manifest](EXP-0003/build-v1/TP4_PREPARATION.json) are retained.
Generated CMake caches are excluded from the shareable evidence.
All 1,052 prepared source files and five executable/script inputs were checked
against their manifests on the remote host before requesting the trial window.

The required read-only reviewer found no remaining major issues after fixes for
four-rank initialization rendezvous, launch error handling, full source pinning
and process-group cleanup. Seven new offline tests passed, including exact GDN
tile/prefetch coverage for both wave counts and a timeout case whose child ignores
SIGTERM after its parent exits. These checks do not establish GPU correctness.

MoE: all four rank rotations, 512/510/508 regular experts, top-10 distinct routing,
real widths, permuted pointer tables and protected trailing slots. Independently
reconstruct sparse reference values before comparing dense variants. Flush
256 MiB before timed launches to avoid decode's active experts being credited as
an unrealistically cache-resident weight set. Time stock rule and each candidate.

GDN: compare stock and candidate outputs and final state byte for byte at lengths
65/75/81/200/2048, H=12/Hg=4, fp32/fp16 state, normal/strong decay, nonidentity
state slot and aliased state replay. Preserve rounded BF16 intermediates and
zeroing of partial chunks. No scan algorithm redesign.

Collectives: reuse upstream rendezvous and ascending-rank exact oracle at actual
2560-wide decode/verify and prefill sizes, including 524288/524352. Sweep only
block/thread counts, drain=3/acq=0, and verify after repeated replay. Retain
external command timeout/fault monitoring; do not widen HyperConn fusion.

## Actual runs and results

The [initial selection run](EXP-0003/kernel-v1-results/status.json) completed all
28 commands in 127.64 seconds. It passed 20 GDN comparisons, 390 MoE form timings,
64 protected-expert oracle/prefix checks and 280 collective geometry/replay checks.
The [parsed rows](EXP-0003/kernel-v1-summary.json) retain the underlying timings;
all command logs and four-BDF telemetry are retained. No kernel fault was logged,
and boot/module identity stayed fixed. These are isolated kernel results; no
end-to-end speedup is established yet.

GDN NW16 was roughly 9–10% faster at 2048 tokens. The candidate now keeps both
schedules and selects NW16 only for N=1, H=12, Hg=4 with initial/final state.
The independent MoE candidate extends two-block gate/up K staging through 650
routed rows and uses the existing eight-group down kernel at 5120–20480 routed
rows, only for the actual TP4 top-10 w4nl64a8h geometry and E=512/510/508. Explicit
test pins retain precedence. The two candidates will be measured separately.
Two additional collective sweeps passed, for 840 collective rows across three
runs. The [three-run summary](EXP-0003/collective-summary.json) shows a roughly
5% improvement for 2560-element one-shot messages at four blocks/128 threads,
but no demonstrated improvement beyond variation at 10240 elements or the
524288/524352 crossover. The 327680-element two-shot gain does not establish an
improvement to the graph's currently selected one-shot path. No collective
production dispatch change is promoted from these measurements.

The [production MoE validation](EXP-0003/moe-validation-results/status.json)
passed all 26 fixtures in 101.69 seconds, including explicit aligned tile pins.
Its stock-rule outputs and routing hashes match the original unpatched MoE implementation
for all 52 projection/shape pairs; the
[kernel comparison](EXP-0003/moe-production-kernel-comparison.json) records this.
The [GDN production validation](EXP-0003/validation-v3-results/status.json) passed
all 20 exact comparisons and a two-sequence/different-head-count fallback smoke.

One prior [validation attempt](EXP-0003/validation-v2-results/status.json)
stopped before any kernel launch: idle runtime-suspended GPUs returned EBUSY for
temperature reads. The successful reruns held normal HIP contexts with 4 KiB per
device allocated solely to keep telemetry readable; no power-management setting
changed. One [serving benchmark attempt](EXP-0003/gdn16-benchmark/status.json)
completed model hashing and six probes, then stopped before BetterBench workload
requests because system Python lacked NumPy. The retry uses the existing
`EXTERNAL_WORKTREE/.venv/bin/python`; its
[client environment](EXP-0003/client-environment.json) is retained. Neither
incomplete attempt establishes a performance result.

## Completed GDN serving comparison

The [three-repeat GDN run](EXP-0003/gdn16-benchmark-r2/status.json) completed all
840 requests in 1090.46 seconds (18.17 minutes). Its
[matched comparison](EXP-0003/gdn16-comparison.json) passes the model, source,
configuration, request and six-response-probe checks. The engine, argv, model
stat and every other loaded library match unchanged EXP-0002 B.

Weighted decode changed -0.075%. Prefill changed +1.719% at 2k, +0.057% at 8k,
+0.138% at 16k, -0.028% at 32k and +0.155% at 64k. No phase meets the predeclared
>2% improvement beyond repeat ranges. The roughly 10% isolated scan-kernel gain
therefore does not establish a useful full-model improvement; do not promote GDN.

All prompt/cache token counts match. Generated-token counts differ for 7/11/11
request groups, all in concurrency phases; see the
[usage comparison](EXP-0003/gdn16-usage-comparison.json). Six fixed response texts
and their usage match, but full long-answer identity/quality is not established.

An [additional exact fallback run](EXP-0003/fallback-results/status.json) passed
60 comparisons in 16.11 seconds: the normal 20 TP4 cases plus 40 different-head
and two-sequence cases, all with both state dtypes, swapped state slots and alias
replay. It uses the reviewed expanded self-test; the production plugin is unchanged.
